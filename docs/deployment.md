# Перенос существующего production — вручную, после ревью

Этот refactor **не развёрнут** автоматически. На текущем сервере есть локальные изменения,
живое меню и загрузки, которых может не быть в Git. Не делайте reset, clean или rsync --delete.

## До переключения

1. Сохранить полную копию каталога приложения, `.env`, текущего image ID и compose config.
   Держать backup вне репозитория с правами доступа только администратора.
2. Сделать `pg_dump` PostgreSQL и snapshot/backup Qdrant. Проверить восстановление.
3. Сравнить незакоммиченные изменения сервера с веткой refactor. Перенести нужные правки
   осознанно. CI не должен затирать их.
4. Собрать новый image **до** остановки рабочего контейнера. Проверить запуск на отдельном
   порту со SQLite и `TELEGRAM_ENABLED=false`, чтобы не запустить второй polling с тем же токеном.
5. Зафиксировать короткое окно обслуживания: остановить старое приложение перед финальной
   копией меню, чтобы редактирование админки не потерялось.

## Данные и конфигурация

- Скопировать **серверный** `instruction.json` в `data/menu.json` — не использовать seed из Git.
- Скопировать всё содержимое `static/images/` в `data/uploads/`, включая `banner.json` и видео.
  Старые `/static/images/...` остаются доступными через compatibility mount маршрута.
- Не копировать собранный frontend поверх загруженных изображений.
- Проверить `DATA_DIR=/app/data`, `STATIC_DIR=/app/frontend/dist`,
  `MODEL_CACHE_DIR=/app/hf_cache`.
- Перенести `tg_key → TELEGRAM_BOT_TOKEN`, `deepseek_key → DEEPSEEK_API_KEY`.
  Legacy aliases ещё читаются, но новая конфигурация предпочтительнее.
- Задать новый случайный `ADMIN_TOKEN` (не короче 16 символов). Токен по умолчанию удалён.
- Задать `DATABASE_URL`, `REDIS_URL`, `QDRANT_URL` с Docker service names.
- Не менять пароль существующего PostgreSQL только переменной `POSTGRES_PASSWORD`:
  переменная образа не меняет пароль в уже инициализированном volume. Сначала безопасно
  изменить пароль роли в БД или использовать действующий и отдельно спланировать ротацию.
- `QDRANT_COLLECTION=pastabar_menu_v2`: старый индекс остаётся для rollback.
- Включить `TELEGRAM_ENABLED=true` и `RAG_ENABLED=true` только при готовых сервисах/ключах.
- `chown -R 10001:10001 data model_weights`: контейнер теперь non-root. Не менять владельца
  postgres_data и qdrant_storage наугад — они принадлежат отдельным сервисам.
- Сохранить текущие named volumes PostgreSQL: Compose project name должен оставаться прежним.

## Проверка после запуска

- `/health`: HTTP 200, затем проверить retrieval state.
- `/`, `/admin.html`: меню, фото и видео отображаются.
- Админка: авторизация новым токеном, изменение цены и повторное чтение.
- Тестовый заказ: цена взята с сервера, контакт присутствует, заказ сохранён,
  ID совпадает в уведомлении. Проверить каждого получателя; Start в боте обязателен.
- Один администратор принимает заказ, второй получает «уже принят».
- В боте: русский/английский запрос, категория, уточнение, изменённая цена.
- Проверить firewall: наружу только SSH/80/443; Qdrant/Redis/PostgreSQL закрыты.

## Rollback

Остановить новый контейнер, вернуть предыдущий image и Compose/env конфигурацию,
старые точки монтирования. Новую таблицу `orders` можно оставить: старая версия её
не использует. Изменения меню, внесённые уже новой админкой, перед rollback отдельно
экспортировать в старый формат — иначе они останутся только в `data/menu.json`.
Не удалять `data`, volumes или старую коллекцию до завершения проверки.
